# 用手机主屏遥控电脑上的 AI：我把 DeepSeek Harness 做成了「手机 App」

> 适合人群：长期在电脑上跑 AI Agent / 仿真 / 训练任务，又想离开工位的人。
> 全程开源，仓库链接在文末。

## 起因

我经常让电脑在家跑几小时甚至一整天的计算任务（MATLAB 仿真、AI Agent 跑批），人不可能一直守着。之前试过远程桌面：重、耗电、还要一直保持连接。

后来发现 DeepSeek Harness 有一个第三方插件能把官方 Web 界面通过 Cloudflare 隧道暴露到手机，但实际用起来有两个坑：

1. 手机上得先扫码配对，之后**每次都要重新扫**？——其实不用，但默认配置没开固定域名，电脑重启域名就变；
2. 最要命的：iPhone「添加到主屏幕」之后，**点开图标永远停在 401**，Safari 里打开却正常。

于是我把它修好，并把整套「手机 App + 7×24 常驻」的配置打包成了一个开源仓库。

## 最后的效果

- iPhone 主屏上一个全屏 App 图标，点开直接是 DSH 官方界面（不是第二套 UI）；
- **手机和电脑是同一个会话**：我在手机上发指令，电脑上同一个会话执行；电脑上跑的任务进度，手机实时看到；
- 电脑重启、App 更新、隧道重连之后，**域名不变、不用重新配对**；
- 电脑开着就随时能用：登录自启 + 托盘常驻 + 每分钟守护自愈 + 不休眠。

## 它是怎么工作的

```
手机（PWA 全屏）
   │ HTTPS 固定域名
   ▼
Cloudflare 隧道 ─► 固定域名中继 https://<id>.dsh-market.com
   ▼
电脑 DSH 宿主
   ├─ 第三方插件 dsh-remote-web-ui：设备配对、门控 /remote 通道
   └─ 我写的 dsh-phone-home：把 PWA manifest 的 start_url 改成 /pair-app
```

关键修复其实就一句话：**iOS 主屏 App 是按 manifest 的 `start_url` 启动的**。官方 manifest 写的是 `"./"`（= 根地址 `/`），根地址需要 harness 的浏览器登录 cookie，于是 401。而插件的 `/pair-app` 只要“设备配对 cookie”就放行，所以我用一个十几行的插件把 manifest 的 `start_url` 指到 `/pair-app`——主屏图标从此不再依赖 Service Worker。

## 两个真踩过的坑（可能对你有用）

**坑 1：微信扫码 401。**
微信/很多 App 内置浏览器不支持 Service Worker，用微信扫配对码，页面能打开但根地址 401。**必须用 iPhone 自带「相机」扫，或者把链接复制到 Safari 打开。** 添加主屏幕也只用 Safari。

**坑 2：cloudflared 下载被墙。**
插件会自动装 Cloudflare 隧道程序，但它从 GitHub 下载，国内经常 `ETIMEDOUT`，而且失败 3 次后会一直缓存失败状态。解决办法是把别处现成的 `cloudflared.exe` 拷进插件目录，或者先 `pnpm add cloudflared`。仓库的排错文档里写了。

## 关于“每分钟检查一次耗不耗资源”

很多朋友问这个。实测：每次检查约 0.3 秒、瞬时几 MB 内存、**0 token**（它根本不调用模型，只是本地看一眼进程在不在），而且通过 wscript 隐藏运行，**不会弹窗**。只有真的发现 App 没在跑，才会把它拉起来。

## 安全问题（必须说清楚）

配对成功的手机 = 这台电脑的完整控制权。所以：

- 只配对你自己的手机；配对链接/二维码别外发；
- 面板里可以逐台撤销设备、或一键「停止」；
- 中继流量经过插件作者的 Cloudflare Worker（可关掉 relay 换成自己的域名隧道）；
- 电脑如果开了自动登录，请自行评估物理安全。
